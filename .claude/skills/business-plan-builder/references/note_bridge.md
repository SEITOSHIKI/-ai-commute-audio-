# note記事への展開（note-article-generator との連携）

事業計画をつくる過程は、そのまま記事の材料になる。数字の作り方、前提の仕分け、競合の調べ方、赤字の計画をどう見せたか、などは読者にとっても役に立つ。ここでは記事の「種」をつくり、note-article-generator スキル（記事を書くスキル）に渡す。

## 流れ
1. 計算モデルから要約をつくる：`node model.js --json > plan_summary.json`（ひな形の `summary()`）で主な数字を書き出し、文章の項目（競合・弱いところ・学び・前提の一覧・次の切り口）を足す。項目は下の例
2. `python3 scripts/make_note_seeds.py plan_summary.json <出力フォルダ>` を実行する
   - `topics.yaml`：記事の企画（topic・angle・article_type・公開判断メモ）
   - `materials/*.md`：各企画の素材（結論・具体的には・使える数字・本人の経験とのつなぎ）。frontmatter は note-article-generator の形式にそろえてある
3. note-article-generator に「この素材で記事タイプ A を書いて」と渡す（`bizplan-note-bridge` エージェントに任せてもよい）

`make_note_seeds.py` が使う項目：`lessons`（A：根拠の出し方）、`plan5`・`plan10`・`blackCondition`（A：赤字の計画）、`assumptions`＝[前提, 値, 確度]の一覧（B：前提の仕分け）、`competitor`・`position`（A：大手との比べ方）、`weakPoints`（A：弱いところ）、`making`（D：資料にするまで）、`ideas`（次の切り口）、`references`（出典URL）。無い項目の企画は出さない。

```json
{
  "slug": "kantsugi",
  "business": "AIグラスで電気工事の作業を記録し、書類と育成を自動化する",
  "customer": "関東の中堅電気工事会社",
  "price": "1拠点10台で年300万円",
  "effect": {"yen": 499, "ratio": 1.5, "breakEvenMin": 23},
  "unit": {"grossProfit": 216, "margin": 72, "ltv": 1571, "cac": 86},
  "plan5": {"sites": 81, "salesOku": 2.7, "op5": -1117, "black": null},
  "plan10": {"black": 6, "cumBack": 8, "op10": 18981},
  "competitor": "日立グループ（保守・安全）",
  "weakPoints": ["普段使いのグラスは現場に弱い", "価格が未検証", "10台では5年で黒字にならない", "大手が来たらブランドで負ける"],

}
```

## 記事タイプの使い分け（note-article-generator の型）
| 型 | 事業計画からの切り口の例 |
|---|---|
| A 主張型 | 「事業計画の数字を作って分かった、根拠の出し方3つ」「5年で黒字にならない計画を、そのまま出した理由」 |
| B 棚卸し型 | 「事業計画の前提を全部並べる：統計・公表・見積・仮説の4つで仕分けた」 |
| D 体験記 | 「研修の事業計画を10分・16枚にまとめるまでの1週間」 |

警告・批評型（C）は事業計画の記事と混ぜない。

## 公開の前に確かめること
note-article-generator の「公開タイミングの判断フロー」に従う。事業計画は職歴と結びつきやすいので、次を必ず確かめる。
- ペンネームの匿名性：勤務先の業界・電圧などの具体的な仕様・資格の組み合わせで、本人が特定されないか
- 発表者名・社内の情報・前職の顧客は書かない
- 事業のアイデアを公開してよいか（研修の提出前に出さない、など）
- 他社名は公表資料の範囲で、出典を付ける

## 事業アイデアを生むための使い方
記事を書くと、読者の反応や自分の書き直しから新しい事業アイデアが出る。記事の最後に「次に検討したい事業の切り口」を1行残しておき、次の事業計画の「1. 構想」で拾う。
